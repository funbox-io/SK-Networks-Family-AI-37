===============================
자연어 처리 과정은 5단계

1. 텍스트 데이터 수집 → 2. 텍스트 전처리 → 3. 토큰화 → 4. 임베딩 → 5. 모델 학습

텍스트 전처리
- 특수문자(문장 부호 등) 제거
- 불용어(stopword) 제거 : 너무 [고침] "자주" 쓰여서 분석에 큰 의미가 없는 "단어"를 제거한다. (예: be 동사, 관사)
  · 원본 "잘 쓰이지 않는 문장" → 불용어는 드문 것이 아니라 흔한 것, 문장이 아니라 단어
  · 빈도 순위를 매기면 위쪽(가장 많이 나오는 쪽)에 불용어가 몰려 있다
  · NLTK 영어 불용어에는 not, no 도 들어 있다 → 감성 분석에서는 빼고 써야 할 수도 있다

텍스트 데이터의 구조 [고침]
- 말뭉치(corpus) > 문서(document) > 문단(paragraph) > 문장(sentence) > 단어(word) > 형태소
- 큰 단위가 작은 단위를 품는 "계층". 말뭉치가 가장 큰 단위
  (예: NSMC 리뷰 20만 개 전체 = 말뭉치, 리뷰 1개 = 문서)

형태소 : 뜻을 가진 가장 작은 말의 단위 (더 나누면 뜻이 사라짐)
단어   : 혼자 쓰일 수 있는 말의 단위 (단, 학교 문법에서는 조사도 단어로 본다 — '꽃이' 는 단어 2개)
- [고침] "사과" 는 더 나눌 수 없는 형태소 하나(명사)이자 단어. 불용어가 아니다 (뜻이 있는 핵심 단어)
  · 풋사과 = 풋(접두사) + 사과(명사),  책가방 = 책(명사) + 가방(명사)
- 실질 형태소 : 실제 뜻 (명사, 동사·형용사 어간, 부사)   예) 꽃밭, 꽃, 피-, 많이
- 형식 형태소 : 문법적 관계만 나타냄 → "조사, 어미, 접사" 세 종류  [고침] "3개를 찾는" 것이 아니라 세 "종류"
  · 한글 불용어로 지우는 것은 주로 조사 · 어미 (접사 '풋-' 을 지우면 뜻이 바뀐다)
===============================
한글과 영어 불용어 차이

한글(불용어) : 조사, 어미 등 "형태소"              [고침] 원본은 '조사' 가 두 번
영어(불용어) : "단어" (대명사, 관사, 접속사, 조동사 등)  [고침] 관속사 → 접속사

예) 꽃밭에 꽃이 많이 피었다
   꽃밭(명사)+에(조사), 꽃(명사)+이(조사), 많이(부사), 피(어간)+었(어미)+다(어미)
   → 조사 · 어미를 지우면 : 꽃밭, 꽃, 많이, 피

토큰화

토큰화 : 텍스트를 의미 있는 단위(토큰)로 나누는 작업 → 결과는 리스트
- 문장 토큰화 : 문장 끝 구두점(. ! ?) 기준
- 단어 토큰화 : 띄어쓰기 기준 (영어)
- 형태소 토큰화 : 형태소 단위 (한글)
영어 = 문장 / 띄어쓰기(단어) 기준,  한글 = 문장 / 형태소 기준
===============================
NLTK (텍스트 토큰화)                                   [고침] NLIK → NLTK (Natural Language Toolkit)

방법은 두 가지 : sent_tokenize(), word_tokenize()

1. sent_tokenize() : "문장 단위 분리"
- 텍스트 전체를 문장 리스트로 쪼갤 때 사용
- 마침표(.), 물음표(?), 느낌표(!)뿐 아니라 약어(Mr., Dr. 등)를 인식해 문맥 기반 분리
- 예: sent_tokenize("Hello Mr. Smith. How are you?")
  -> ['Hello Mr. Smith.', 'How are you?']                 (실행 결과와 같음)

2. word_tokenize() : "단어 단위 분리"
- 띄어쓰기뿐 아니라 문장 부호(쉼표, 따옴표 등)와 축약(n't)을 단어와 분리
- 예: word_tokenize("Don't hesitate, just do it.")
  -> ['Do', "n't", 'hesitate', ',', 'just', 'do', 'it', '.']   (실행 결과와 같음)

* 필수 사전 패키지
  nltk.download('punkt_tab')   # 문장 부호 규칙 (구버전 nltk 는 'punkt')
  nltk.download('stopwords')   # 불용어 목록
  stopwords_list = nltk.corpus.stopwords.words('english')   # 영어 불용어 198개 (NLTK 데이터 버전마다 다름)
===============================
데이터 타입 : 리스트

문장은 마침표(. ! ?)를 기준으로 '인식'한다
[고침] 단어는 "띄어쓰기 + 구두점" 기준으로 '인식'한다 (마침표 기준은 문장)

단어 단위 토큰화 문제점 : OOV(Out-Of-Vocabulary)
- 신조어 · 오타 · 조사가 붙은 변형이 사전에 없으면 전부 [UNK] 하나가 된다
- 실습 : NSMC 학습 리뷰로 어절 사전 3만 개를 만들면 테스트 어절의 36% 가 OOV

서브워드 토큰화
- 서브워드 : 단어를 더 쪼갠, 의미를 가진 최소한의 글자 조각 (레고 블록)   [고침] "쪼깬 뜻" → 쪼갠 조각
  예) unhappiness → un + happi + ness
- 대표 알고리즘 : BPE, WordPiece
===============================
BPE (Byte Pair Encoding)

1) 모든 단어를 문자 단위로 분리 → 초기 단어 사전 = 문자들
   hug(10) pug(5) pun(12) bun(4) hugs(5) → b, g, h, n, p, s, u (7개)
2) 이웃한 두 토큰(바이그램) 쌍의 빈도를 센다. 단어 안의 쌍은 그 단어의 빈도만큼
   [고침] hug 하나에서 (h,u) 10번, (u,g) 10번 (원본 "hu 5번, ug 5번" 은 hugs 몫)
   같은 쌍끼리 합치면 (u,g) 20, (p,u) 17, (u,n) 16, (h,u) 15, (g,s) 5, (b,u) 4
3) 가장 많은 쌍을 합쳐 사전에 추가하고, 단어를 다시 표시 → 2) 로 반복
===============================
바이그램 = 이웃한 두 개를 묶은 것

1단계 후 (ug 추가) 단어 사전 : b, g, h, n, p, s, u, ug
hug  -> h, ug     -> (h, ug) 10회
pug  -> p, ug     -> (p, ug) 5회
pun  -> p, u, n   -> (p, u) 12회, (u, n) 12회     [고침] (u,p) → (u,n)
bun  -> b, u, n   -> (b, u) 4회, (u, n) 4회       [고침] b,,u,n → b, u, n
hugs -> h, ug, s  -> (h, ug) 5회, (ug, s) 5회
[고침] 원본 "(h.ug)1whdfb -> 10종류" 는 한/영 전환 오타(whdfb = 종류) → (h, ug) 10회

합치면 (u,n) 16 → un 추가,  (h,ug) 15 → hug 추가,  (p,un) 12 → pun 추가
최종 단어 사전 : b, g, h, n, p, s, u, ug, un, hug, pun
드문 pug, bun, hugs 는 p+ug, b+un, hug+s 로 표현
===============================
서브워드 토큰화의 장점
- 사전에 없는 단어(신조어 · 오타)도 서브워드 + 문자 조합으로 토큰화 → OOV 문제 해결   [고침] OVV → OOV
  (실습 : 노잼각 → 노잼 + ##각,  꿀잼보장 → 꿀잼 + ##보 + ##장)
- 적은 수의 조각으로 많은 단어 표현 → 가벼운 용량
- walk / walking / walked 처럼 공통 조각으로 뿌리가 같음을 학습

WordPiece : BPE 와 비슷하지만 병합 기준이 "빈도" 가 아니라 점수 f(ab) / (f(a) × f(b))
- 단어 중간 · 끝 조각에 ## 를 붙인다. 복원 : ## 없으면 띄우고, ## 있으면 앞에 붙임

토큰화 클래스
- BertWordPieceTokenizer (tokenizers) : 말뭉치로 단어 사전(vocab.txt) 생성
- BertTokenizerFast (transformers)    : vocab.txt 로 문장을 토큰 → id → BERT 입력([CLS] ... [SEP]) 으로
  · 주의 : 대소문자 옵션 이름은 lowercase 가 아니라 do_lower_case
  · 주의 : 사전을 strip_accents=False(음절 단위)로 만들었는데 토큰화 때 빼면, 한글이 자모로 분해되어 전부 [UNK]
           학습 · 토큰화 둘 다 True 면 자모 단위 사전이 된다 (갔어요 → 가 + ##ᆻ어요, 교재 p.27 의 ##ᆻ다)

단어 사전을 만들고 순서대로 토큰화해야(토큰 → id) 학습이 가능하다.

텍스트 데이터가 있어야 머신러닝이든 딥러닝이든 학습이 가능하다.   [고침] 덱스트 → 텍스트
